## Protocol

- Codex CLI `0.145.0`, model `gpt-5.6-sol`, reasoning effort `xhigh`.
- Each ephemeral session received only the issue, package metadata, HTML/CSS stubs, store and app stubs, and one public store test.
- The workflow, protected Playwright tests, reference implementation, negative fixture, other branches, and prior task history were absent from the session workspace.
- The prompt prohibited network access, external paths, test edits, package edits, history inspection, and commits. The observed tool events complied.
- After each turn, the host froze the exact four produced blobs, ran the protected verifier, visually inspected the generated screenshots, and published the same Git tree to a private GitHub PR.
- Elapsed time measures clean-baseline readiness through host freeze. Token counts come from the CLI's `turn.completed` event.

## Contract calibration

The final contract accepts an independent reference implementation at 6 / 6 and rejects a planted false-green search implementation at 5 / 6 even though its public store test passes.

The first frozen Agent implementation exposed two over-specific assertions in the developing contract. One assumed only one visible status label; the implementation legitimately rendered both a badge and a definition-list value. The other required the reference phrase `Moved from Open to Investigating` even though the issue only required a short activity entry. The assertions were corrected to validate semantic behavior: a visible status exists, activity grows after transition, and activity persists after reload.

The Agent source was not changed during those corrections. The early runs are classified as invalid contract calibration runs, not candidate failures or repair rounds. The same frozen commit then passed 6 / 6, and the final contract was rerun against both the reference and negative calibration fixtures.

## Interpretation

The browser task used roughly twice the wall time and substantially more output than the earlier checkout task, while still achieving 2 / 2 first-attempt acceptance. This supports the gate's ability to verify real multi-file UI work, not a general claim that browser Agents are always correct.

The configured custom provider did not expose billed cost or a pricing contract. The recorded total is 442,860 input tokens, including 361,728 cached input tokens, plus 34,846 output tokens and 9,544 reasoning output tokens.

The most important new finding is about verifier governance: protected tests can create false negatives when they encode one implementation's presentation or wording instead of observable requirements. Production adoption needs contract review and calibration fixtures in addition to protecting the test files from candidate edits.
